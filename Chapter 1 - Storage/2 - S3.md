## Core Concepts - Answers

1. **Data Model & API:**
- S3 object model:
    - buckets - A bucket is a container for objects.
    - objects - An object is a file and any metadata that describes that file.
    - keys - The name that you assign to an object. You use the object key to retrieve the object.
    - versions - Within a bucket, a key and version ID uniquely identify an object. The version ID is a string that Amazon S3 generates when you add an object to a bucket.
- How it differs from a hierarchical file system?
Flat Storage Structure, where it organize all files at the same level, without directories or subdirectories, akin to placing all documents in a single folder. Relies on metadata tags and unique identifiers to categorize and retrieve files, compensating for the lack of nested directories.
- Typical REST operations - open, download, copy, clean-up buckets.
- Why is the namespace flat rather than directory-based? In directory-based, to find a file, the computer must look at the root folder, then the subfolder, then the next subfolder. In big amount of data, the lookups becomes slower. In addition, in block storage the data breaks into fixed-size chunks and stored them in disk which supply extremly fast latency. But Only one instance can use it at a time. Much of the space might remain unused. It doesn’t scale automatically. In contrast to them, you give S3 your data, and S3 gives you a unique Key (the ticket). When you want your data back, you present the Key. Because there is no hierarchy (no “walking down the folder tree”), retrieving the 1st file is just as fast as retrieving the 1 billionth file. This is why S3 can hold petabytes of data without slowing down.

- How is metadata stored and retrieved in S3-compatible systems? When you upload a file to S3, it is stored as an S3 object. Objects consist of the file data and metadata that describes the object.
